# 产品图片批量改名 — 固定工作规则

## 范围
- 工作目录：`产品/新程序/`（相对于仓库根目录）。
- 目标：读取用户提供的 NUMERACION 最新版本表格，根据图片文件名中的**旧内部码**找到对应的**新内部码**，替换文件名中的内部码，图片本身保持不变。
- 用户后续可能会提供更多图片或更新的表格；以每次明确指定的表格版本为准，不默认为当前仓库已有文件就是最新版。

## 必须遵守
1. 先核对表头和实际字段，确认旧内部码、新内部码所在列；编码作为**文本**处理，保留前导零。
2. 优先用原九位内部码进行精确匹配；不根据图片内容、产品名称或近似编码猜测对应关系。
3. 同一旧码映射多个新码、无法匹配、空值或新名字冲突时，跳过该图片并列入异常清单，交用户确认。
4. 只变更文件名，不重新编码、裁剪、压缩或改变图片画质；保留文件扩展名，禁止覆盖原文件。
5. 先生成“旧图片名 → 新图片名”的预览清单，校验后再批量执行；原图保留一份可恢复副本。
6. 输出成功、未匹配、冲突、重复的数量及明细，检查成功重命名的文件总数及名称唯一性。
7. 新增的工具脚本与说明保存在本目录，便于下次复用。除非用户明确要求并确认检查结果，不自动把大量原图或带敏感信息的价格文件提交到 GitHub。
8. 未提供图片、编码表或关键字段时，明确报告缺少什么，不伪称任务完成。
